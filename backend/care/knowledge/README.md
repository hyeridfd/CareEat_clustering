# 근거 문헌 (RAG)

돌봄 솔루션이 LLM의 일반 지식이 아니라 **지침·매뉴얼 문단**에 근거하도록 하는 부분입니다.

```
care_rules.py   어떤 조치를 할지 (범위를 정한다 — 이건 그대로)
retrieval.py    그 조치의 근거 문단을 지침에서 찾는다
LLM             후보 조치 안에서 개인화하고 [G1] 처럼 인용한다
validate()      없는 번호의 인용을 지우고, 실제 인용된 출처만 저장한다
```

검색이 조치를 **만들지 않습니다.** 기존 가드레일(후보 rule_id 밖의 조치 제거)은 그대로입니다.

## 처음 한 번

1. Supabase SQL 편집기에서 `backend/sql/care_schema_v6.sql` 실행
   (pgvector 확장이 함께 켜집니다)
2. `backend/.env` 에 `OPENAI_API_KEY` 가 있는지 확인 — 임베딩에 씁니다
3. `sources.json` 에 문헌을 등록하고 `docs/<id>.md` 파일을 둡니다
4. 적재

```bash
cd backend
pip install pypdf          # PDF 를 넣을 때만
python scripts/ingest_guidelines.py --dry-run    # 쪼개진 모양 확인
python scripts/ingest_guidelines.py              # 업로드
```

5. 앱에서 솔루션을 다시 생성하면 조치·식사지침 끝에 위첨자 번호가 붙고,
   아래에 '근거 문헌' 목록이 나옵니다.

## PDF 에서 만들기

```bash
python scripts/pdf_to_md.py 매뉴얼.pdf --id LTC_MEAL_MANUAL --check      # 글자가 나오는지 먼저 확인
python scripts/pdf_to_md.py 매뉴얼.pdf --id LTC_MEAL_MANUAL --pages 12-58
```

`docs/<ID>.md` 초안이 만들어집니다. 조항 제목은 `## 3.2 ...`, 쪽은 `<!-- p.34 -->` 로 들어가고
적재할 때 각각 section·page 로 저장돼 각주에 `— 3.2 저염식 제공 원칙 · p.34` 처럼 찍힙니다.

**초안은 반드시 원문과 대조해 손질하세요.** 목차·머리말·표가 섞여 들어옵니다.
`--check` 에서 글자 수가 거의 0 이면 스캔본이라 텍스트 추출이 안 됩니다 (OCR 필요).

## 문서 작성 요령

마크다운이 가장 잘 맞습니다. `##` 제목이 근거 각주의 조항명이 되고, 빈 줄로 문단이 나뉩니다.
`docs/_TEMPLATE.md` 를 참고하세요.

```markdown
## 3.2 저염식 제공 원칙

국·탕은 건더기 위주로 배식하고 국물은 반 컵 이하로 제공한다. ...
```

한 문단은 400~700자 정도가 검색에 가장 잘 걸립니다. 표는 문장으로 풀어 쓰는 편이 낫습니다.
영문 지침이라면 한국어 요지를 같은 문서 안에 함께 적어두면 검색이 훨씬 잘 됩니다.

## 저작권

- **넣어도 되는 것**: 공공누리 지침·매뉴얼, 오픈액세스 논문, 연구실이 직접 쓴 문서
- **넣지 말 것**: 시중 서적·유료 지침서의 **원문 그대로**
- 유료 자료는 권고의 **요지를 자체 문장으로 다시 써서** `license: "내부요약"` 으로 등록하고,
  `citation` 에 원 출처를 정확히 적습니다.

## 환경변수 (선택)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `RAG_ENABLED` | `1` | `0` 이면 지침 검색을 건너뛴다 |
| `EMBED_MODEL` | `text-embedding-3-small` | 바꾸면 차원(1536)도 SQL에서 맞춰야 한다 |
| `RAG_QUERIES` | `4` | 한 어르신당 만드는 검색 질의 수 |
| `RAG_PER_QUERY` | `3` | 질의당 가져올 문단 수 |
| `RAG_SNIPPETS` | `8` | 프롬프트에 넣을 문단 총수 |
| `RAG_MIN_SIM` | `0.2` | 유사도 하한 — 낮으면 엉뚱한 문단이 섞인다 |

## 비용

문헌 적재는 한 번뿐이고 `text-embedding-3-small` 기준 1,000문단에 1센트 수준입니다.
솔루션 생성 때는 어르신 1명당 질의 임베딩 1회 + 프롬프트 3천자 정도가 늘어납니다.

## 점검

`GET /care/knowledge-status` (담당자 토큰) — 문헌별 문단 수·임베딩 수와 설정을 돌려줍니다.
지침이 하나도 적재돼 있지 않으면 검색은 조용히 건너뛰고, 기존 방식 그대로 솔루션이 만들어집니다.
